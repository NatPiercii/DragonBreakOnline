# Game server plugin data

The SkyMP server must load exactly the plugins players load, in the same order,
or form IDs stop lining up (`FromFormId failed due to invalid file index` in the
server log). This folder is the source of truth for that set.

| File | What it is |
|---|---|
| `loadorder.txt` | The server's `loadOrder`, one plugin per line: 5 base masters, the 5 Creation Club files every 1.6.1170 install has, then the collection's plugins. |
| `SHA256SUMS` | Expected hash of every file the server needs: each plugin plus `Skyrim - Misc.bsa`. Base files are the clean Steam 1.6.1170 versions. |
| `build-bundle.py` | Verifies a Data folder against `SHA256SUMS` and packs the files into a tar. |
| `apply-server-plugins.sh` | Installs a bundle on the game server CT and sets `loadOrder`, with backup, health check and automatic rollback. |

Game and mod files are never committed; only their names and hashes live here.

## Updating the server

1. On a PC with Skyrim SE **1.6.1170** and the collection deployed (Vortex), build the bundle:

   ```bash
   python deploy/skyrim-data/build-bundle.py --data "C:/Program Files (x86)/Steam/steamapps/common/Skyrim Special Edition/Data"
   ```

   It refuses to build if any file is missing or differs from `SHA256SUMS`.
2. Copy `dragonbreak-server-plugins.tar` and `apply-server-plugins.sh` to the Proxmox host (the `dragonbreak` share at `/mnt/disk3/dragonbreak` works) and run as root:

   ```bash
   bash apply-server-plugins.sh dragonbreak-server-plugins.tar
   ```

   The game server is down for about a minute. The previous data folder is kept at
   `/opt/skyrim-data.bak-<UTC>` and the previous settings at
   `/opt/skymp-config-backup/server-settings.json.<UTC>`.

`server-settings.json` is gitignored and regenerated by the build, but the
generator keeps `loadOrder`, so this survives the 5-minute auto-updater.

## Changing the plugin set

Edit `loadorder.txt` and `SHA256SUMS` together, rebuild the bundle, apply it, then
rebuild the launcher's install manifest (`skymp5-backend/scripts/vortex-reference`),
which reads this same `loadorder.txt`. Every plugin's masters must load before it;
SkyMP stops at startup on an unresolved master.
